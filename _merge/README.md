# _merge/ —— 对方发新版时，一键贴回我们的改动

## 背景

对方习惯**整包重发**代码。直接覆盖会丢掉我们的东西：

- 面板接线（H5 只读面板）
- 推送总闸 / 小信号开关
- BOLL「三轨开口向上」的 15m+1h 口径
- 两处崩溃修复（对方代码里的未定义变量）
- 日志逐行刷新
- 新闻缓存

手工重贴每次要 1 小时且容易漏。这个目录解决这件事。

## 用法

```bash
# 1) 试运行（只报告，不写任何文件）
python _merge/reapply.py <对方新包的目录>

# 2) 确认无误后写入（每个文件自动备份为 xxx.py.bak_<时间戳>）
python _merge/reapply.py <对方新包的目录> --write

# 3) 只处理指定文件
python _merge/reapply.py <对方新包的目录> --files main.py,news.py

# 4) 写到别处（不碰工作区，适合先验证）
python _merge/reapply.py <对方新包的目录> --write --out-dir /tmp/merged
```

## 原理：三方合并

    base   = _merge/base/<文件>   对方 v3.7 —— 我方改动所基于的那个版本
    ours   = ./<文件>             我方当前版本
    theirs = 对方新包里的 <文件>

`git merge-file` 三方合并：

| 情况 | 结果 |
|---|---|
| 只有他改了 | 自动带进来 |
| 只有我们改了 | 自动保住 |
| 两边都改了同一处 | 冲突 → **默认取他的** |

**为什么冲突默认取他**：他的改动通常是「重构/搬迁旧代码」（例如把 BOLL 破轨
抽成 `check_boll_breakout()`、把移动止盈改成动态 ATR），旧写法就该被取代。

## 语义 fixup（三方合并解决不了的）

有些地方需要「两边都要」，合并器做不到，用 FIXUPS 补：

| 文件 | fixup | 做什么 |
|---|---|---|
| `news.py` | 新闻缓存壳 | 他换了新闻源；保留我们的缓存 → 拆成 `get_latest_news()`（缓存壳，我方）+ `_fetch_news()`（他的抓取） |
| `notifier.py` | webhook 默认值 | 他硬编码了他的新群 webhook；我方有 env/config_local 覆盖链。合并后我方那行会**清空**他的群 → 改成 `os.environ.get(...) or FEISHU_WEBHOOK`，让他的群当默认值 |

## 安全网

合并后会做**接缝自检**：

- 我方接缝缺失 → **拒绝写入**，退出码非 0
- 他的新功能缺失 → 报告（提示可能没合进来）

默认试运行，只有显式 `--write` 才会动文件，且写前自动备份。

## 维护

- 我们**新增**一个 main.py 接缝时，记得同步加进 `reapply.py` 的 `SEAMS`，
  否则下次合并这个新接缝不会被检查（漏了也不知道）。
- 对方**新增**重要功能时，可加进 `FEATURES` 作为提醒。
- 基线 `_merge/base/` 是**对方 v3.7**，不要动。等双方都稳定后，
  可以考虑把基线推进到某个新版本（否则合并的"共同祖先"太旧，冲突会变多）。
